# Kali_lock
天猫校园一建跳转，避免广告和等待，适合我这种低精力人群，每次开门都要一分钟emm.不过挺鸡肋的，因为只是一个跳转，不能删除天猫校园。我找到了跳转蓝牙的函数，但是目前还要天猫小院提供用户信息授权。这个没办法，掌门物联官网什么东西都没有，没有sdk，没有产品软件说明，服了。如果用人解决了，欢迎贡献

## 当前版本与使用说明

手机端开门页快捷入口：**直接点击“宿舍开门助手”应用图标，请求进入天猫校园开门页。** 不再先进入助手设置，也不需要额外点击、小组件或无障碍权限。需要设置时长按图标，选择“助手设置”。本入口只导航，不点击开锁。

**当前版本 0.2.1：图标直达已实现。替代路由的冷启动导航检查记录到路由入口 → 开门页容器，观察窗口内无首页/启动页生命周期事件。仍依赖天猫校园的登录、通行权限和蓝牙能力；未实现后台开门、独立平替或自动开锁。2–3 分钟延迟原因尚未定位。**

补充：已旁观用户通过原应用正常开门一次，用户报告门打开；取得目标应用 BLE 事件及固定开门页地址，见 [LIVE-OBSERVATION.md](LIVE-OBSERVATION.md)。前端依赖原应用的原生桥接，尚未实现脱离原应用界面的开门。

静态核对版本：天猫校园 5.7.2（50007002）、5.8.0（50008000）；设备导航实测为 5.8.0。其他版本会停止并提示。旧版无障碍自动化仍保留在设置与小组件中，独立于图标直达，不是默认路径。

## 使用顺序

1. 安装或覆盖更新助手，保留已正常登录的天猫校园。
2. 解锁手机，直接点“宿舍开门助手”图标。它只发送固定开门页导航请求，不启动旧版点击任务。
3. 页面到达后，由用户在合适位置按原应用正常流程操作。日常导航无需电脑或 ADB。
4. 长按助手图标 →“助手设置”，可查看状态。原来的桌面图标组件名保留，升级后应使用新行为。
5. 如果原应用更新或入口失败，从原应用正常进入；保留故障现象，不通过循环请求掩盖失败。

旧版小组件/演练功能仍需用户手动授予无障碍，并完成其独立验证，见设置说明。使用当前图标入口无需开启无障碍。系统事件没有出现首页，不等同于逐帧视频证明没有旧画面；系统启动动画、网页加载和后续登录跳转仍可能出现。

## 项目文件

- `app/`：独立编写的 Android Java 源码和资源，无网络权限。
- `tests/FlowTest.java`：执行状态机检查，不使用手机或真实门锁。
- `tools/build.py`：离线编译、测试、签名和校验。
- `tools/export_source.py`：按允许列表导出不含私有资料的源码包。
- [ANALYSIS.md](ANALYSIS.md)：静态证据、未知项与方案依据。
- [VENDOR-FINDINGS.md](VENDOR-FINDINGS.md)：掌门物联证据、候选型号及独立接入仍缺的授权条件。
- [LOGIN-INTEGRATION.md](LOGIN-INTEGRATION.md)：登录依赖、网页授权线索与后台调用入口的静态检查结果。
- [VALIDATION.md](VALIDATION.md)：实际测试结果和未完成验收。
- [BUILD.md](BUILD.md)：复现构建、安装和恢复步骤。
- [PRIVACY.md](PRIVACY.md)：无障碍权限、数据处理和执行边界。
- `private/`：只在本机保存的原 APK、反汇编、开发密钥及助手界面检查图，不可公开。
- `dist/`：本项目 APK 和源码 ZIP，不自动发布。

## 范围

仅分析自己的手机、账号和已有通行权限。不绕过认证，不伪造凭证，不枚举门禁，不测试其他账号。实际开锁由用户在门边明确配合，不自动重复触发。

最终目标：手机独立运行，不依赖持续 ADB。是否可脱离原应用尚未知。

目前已交付的是第一级目标：图标直达原应用的开门页。第二级“不展示原应用、后台开门”和第三级“卸载原应用后独立开门”尚未实现，需另行验证正常认证与集成方式。

## 已有证据

- 前一阶段 ADB 实测：型号 PLE110，Android 16 / API 36。
- 应用包名 com.tmall.campus.and；初次检查 5.7.2 / 50007002，安装助手时重新核对已变为 5.8.0 / 50008000；未由本项目升级原应用。
- 桌面启动 Activity：com.tmall.campus.launcher.SplashActivity。
- 用户观察：启动加载约 2–3 分钟，首页广告多，开门后跳广告；尚无分段实测。
- 用户检查：长按桌面图标没有开门快捷项。此结果不能排除深链接或其他页面入口。

## 当前改动与恢复

电脑端启动过 ADB 服务并创建本研究目录；初版助手经用户手机端确认后安装成功。没有安装第三方模块、修改系统安全设置、清除原应用数据或触发开锁。可用 adb kill-server 停止电脑端服务（会影响其他 ADB 会话）。

已从手机复制两个已观察版本的 base APK 到 private/，仅供本地静态分析，目录权限 700，APK 权限 600。分析工具放在 /tmp/dorm-door-analysis-python，不修改系统 Python。关闭助手无障碍服务、移除小组件并卸载助手即可恢复；原应用无需恢复。临时工具与本地 APK 可在研究结束后手动删除，不自动清理。
